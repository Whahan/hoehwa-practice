### 0.2 목표와 범위
- **목표**: 영어를 진짜 0부터 시작하는 한국인 성인이 **18개월(코스 72주), 하루 45분**으로 캐나다 워킹홀리데이에서 생활하고 일할 수 있는 회화 수준에 닿게 하는 새 영어 코스. "가르치고 나서 묻는" 새 레슨 구조, 배운 단어·문형만 나오는 제약, 말하기 사다리, 수준 맞춤 AI 대화, 주간·월간 점검, 워홀 상황 미션을 갖춘다.
- **범위**: 영어만. 기존 일본어 기능·화면·데이터는 하나도 바꾸지 않는다(시험으로 확인). 기존 영어 12개월 길(Tatoeba 레슨)은 지우지 않고 "예전 길"로 병행한다.
- **하지 않을 것**
  - 일본어 코스, 일본어 코드 수정.
  - 이미지·사진·영상·실제 사람 녹음(저작권·`check_no_media.ps1`). 캐나다 억양 실제 음성은 사용자 승인 후 R4 선택 항목(§8.4).
  - 쓰기·읽기 코스 확장(읽기는 기존 읽기 화면을 그대로 둠). 문법 시험 대비·점수 인증.
  - 무료 AI 이외의 새 AI 서비스, 새 하단 탭(폰 5개 그대로), 새 autoload(`project.godot` 변경 0), 안드로이드 권한 추가(`export_presets.cfg` 변경 0).
  - 새 서버 라우트 추가·`lan.py` 변경·동기화 스키마(`SyncDoc.SCHEMA`) 변경(전 릴리스 0). 서버·동기화 쪽 변경은 R1 = 0, R2 = `/chat` 선택 필드뿐, R3 = 카드 상한·`checks` 키 사용뿐(§12).
  - 버전 올리기·릴리스(오케스트레이터).

## 1. 학습 설계 원칙과 "가능"의 정의

### 1.1 "가능"의 기준 (정직하게)
- **코스가 끝났을 때의 목표**: 말하기·듣기에서 **CEFR A2+ 전반 + 워홀 상황 27개(§8.1) 안에서는 B1 낮은 수준**. 즉 준비된 상황에서는 막힘이 있어도 되묻고 풀어 말하며 용건을 처리하고, 처음 보는 주제에서는 A2 수준에서 버틴다. **일반 B1 을 보장하지 않는다.**
- **근거와 한계**
  - 시간: Cambridge 의 안내 학습 시간 표는 A2 Key 약 180~200시간, B1 Preliminary 약 350~400시간(처음부터의 누적, 약식 지표. [Cambridge Helpdesk](https://support.cambridgeenglish.org/hc/en-gb/articles/202838506-Guided-learning-hours)). 이 코스의 총량은 72주 x 7일 x 45분 = **378시간**(달력 78주 기준 410시간까지). 안내(교사)가 있는 시간 기준이므로 혼자 앱으로 하는 공부는 **효율이 낮을 것**(추측, 보통 같은 시간에 한 단계 아래). 그래서 "B1 낮은 수준"은 **상황을 좁혀서** 약속한다.
  - 어휘: 일상 구어를 95% 알아들으려면 약 3,000 단어족이 필요하다는 보고가 있다(Adolphs & Schmitt 2003 의 인용, **2차 자료 — 원문 확인 필요**; [Schmitt & Adolphs 2003 초록](https://benjamins.com/online/ebop/publications/32356), [Nation 2006](https://www.wgtn.ac.nz/__data/assets/pdf_file/0018/1626120/2006-How-large-a-vocab.pdf)). 이 코스는 능동 약 1,800 + 수동 약 950 = **약 2,750**(항목 수, 단어족이 아님)이라 **일반 구어의 90~95% 부근**이고(추측), 워홀 상황 어휘는 집중해서 가르치므로 그 안에서는 더 높다. 나머지 5~10% 는 **되묻기·추측·풀어 말하기 전략**(12주부터 계속 훈련)으로 메운다.
  - 소리: 앱의 듣기는 합성 음성(미국 영어, 또박또박)뿐이다(F12). **실제 현장의 빠른 말·웅얼거림·캐나다 억양·전화 음질은 앱만으로 충분히 훈련되지 않는다**(§8.4, §15.1 R-3). 사람 피드백도 없다(AI·자동 채점뿐).
- **"가능"을 재는 기준(앱 안의 지표, 초기 추측 임계값)** — 72주차 최종 평가(§7.3)에서 모두 만족하면 "코스 완료":
  | 영역 | 기준 |
  |---|---|
  | 상황 말하기 | 워홀 상황 미션(§8.1, 27개) 중 **무작위 5개에서 4개 이상**을 **힌트 없이** 목표 80% 이상 달성(27개 모두 한 번은 별 2개 이상 받았을 것) |
  | 듣기 | 1.0배속 대화 20개(상황 다양, 목소리 4종 이상)에서 핵심 정보 질문 75% 이상 |
  | 말하기 점수 | 월말 말하기 평가 마지막 3회 평균 75/100 이상(§7.2) |
  | 어휘 | 능동 단어 100개 무작위 표본 회상(뜻→영어 입력) 90% 이상 |
- 위 지표는 "앱 안에서 이만큼 한다"는 뜻이다. **실제 캐나다 현장 성공을 보증하지 않는다.** 사용자에게 보이는 글에도 이 한계를 쓴다(§14 Z).

### 2.4 캐나다 워홀 상황을 언제 어떻게 넣는가
- **8주차부터 매주 한 줄씩**(카페 주문), 12주부터 되묻기·워홀 직종 어휘, 21주부터 날씨·교통·식당 같은 생활 장면, 33주부터는 주 단위로 **도착 → 정착 → 구직 → 일터** 장면이 주제 자체가 된다(§2.3 굵은 글씨). 어휘는 해당 주에 처음 나오고, 이후 미션·점검에서 계속 섞인다.
- 지역 표현·철자는 **약 40개를 "캐나다 노트"로**: 철자(colour, centre, cheque, licence, grey, favourite), 어휘(washroom, toque, loonie/toonie, double-double, pop, runners, hydro, stat holiday, postal code, province), 문화(팁, 섭씨·km, "Sorry" 습관, "eh" 알아듣기). 정답 입력은 **미국식·캐나다식 철자를 둘 다 인정**(`alt` 필드), 화면 표기는 캐나다식을 기본으로 한다. 지역 표현은 **알아듣기 위주**이며 말하기 필수로 요구하지 않는다.
- 사실(절차·금액·번호)은 **원고에 숫자로 박지 않는다**: 최저임금, 세율, 필요 서류 목록 같은 것은 달라지므로 "공식 사이트에서 확인하세요" 노트와 `fact_date`(확인한 날짜)만 둔다(R3 작업 지시에 포함). 대사의 이름·주소·전화번호는 가상(전화번호는 `555-01xx` 형식)이다.

## 3. 새 레슨 흐름

### 3.1 하루 "새 내용" 15분 단위 (`unit kind = "new"`)
| 단계 | 하는 일 | 문제 종류(`type`) | 대략 개수·시간 |
|---|---|---|---|
| ① 소개 | 새 단어 카드(영어 + 소리 + 한국어 뜻 + 예문 1), 문형 카드(틀 + 한국어 문법 설명 + 예문 3). 사용자가 [다음]을 누르며 소리를 듣는다 | `teach_word`, `teach_pattern` | 단어 6~7 + 문형 1~2 = 약 8장, 약 4분 |
| ② 알아보기 | 보고·듣고 뜻 고르기(보기 2~4개) | `recognize` | 단어당 2 = 약 12, 약 2분 |
| ③ 떠올리기 | 뜻을 보고 영어 고르기 → 영어 직접 쓰기 | `recall` | 단어당 2 = 약 12, 약 3분 |
| ④ 조립 | 한국어 문장을 보고 영어 타일 순서 맞추기 | `build` | 5, 약 2분 |
| ⑤ 듣기 | 들은 문장의 뜻 고르기 / 짧게 받아쓰기 | `listen` | 4, 약 1.5분 |
| ⑥ 말하기 | 듣고 따라 말하기, 문형 바꿔 말하기(녹음·채점 또는 자가 평가) | `speak` | 5, 약 3분 |
- **숙달 루프**: 틀린 문제는 같은 단계 끝에 한 번 더 나온다(최대 2번). 단위가 끝나면 맞힌 비율을 기록하고, 틀렸던 항목은 복습 카드로 들어간다.
- **그 날의 새 단어·문형 전부**가 복습 카드가 된다(능동 단어, 문형 틀 문장 1개, 그 주 대화 핵심 문장 최대 2개). 수동 단어는 카드가 아니다(카드 수 관리).
- 같은 구조의 다른 단위: `listen`(듣기 8분: 배운 문장 듣기 세트, 속도 선택), `speak`(말하기 12분: 그날의 사다리 칸, §4), `check`(주간 점검 12문제, §7.1), `month`(월말 말하기 평가, §7.2), `recap`(복귀 점검, §6.2). 한 화면 플레이어가 모두 처리한다(E4).

### 3.2 문제 종류와 데이터 (필드 이름은 §10.4 가 기준)
- `teach_word`·`teach_pattern`: 정답 없음. 소리 재생 버튼, [다음].
- `recognize`: 모드 `en_ko`(영어를 보고 한국어 고르기), `hear_ko`(듣고 한국어 고르기), `hear_en`(듣고 영어 고르기). 보기는 **배운 단어 중 같은 품사**에서, 뜻이 정답과 겹치지 않는 것만(§3.3 규칙 R4).
- `recall`: 모드 `ko_en_choice`(한국어 → 영어 고르기), `ko_en_type`(한국어 → 영어 쓰기: 철자 정확히, 한 글자 차이는 "거의 맞아요" 안내 후 한 번 더 기회).
- `build`: 한국어 문장 → 영어 타일(정답 + 배운 단어 중 비슷한 오답 타일 최대 2). 정답은 원고가 준 정답 목록(`accept`)과 대조.
- `listen`: `choose_ko`(뜻 고르기) / `type`(받아쓰기, 3~6단어).
- `speak`: `repeat`(따라 말하기), `substitute`(문형 바꿔 말하기: 한 단어를 바꿔 말하기). PC 는 `/score`, 폰 단독·채점 불가는 자가 평가(통계에 정확도로 세지 않음). `SpeakDrill` 재사용.
- `dialogue_script`: 대본 대화(§4).
- 모든 문제는 `tts`(재생할 글)를 가진다. 숫자·기호·약어는 원고가 **읽는 글 `say`**(예: `$5.99` → `five ninety-nine`)를 따로 준다. TTS 가 알아서 읽게 두지 않는다(F14, §9.3).

### 3.3 "배운 것만 나온다"를 지키는 방법 (3중 검사)
- 모든 단어·문형·문장에 **도입 순서 `o = w*10 + d`**(주 w, 일 d)가 있다. 예: 5주 2일 = 52.
- **규칙**
  - R1(문장): 문장의 모든 토큰이 낱말 목록의 항목이고, 그 항목들의 `o` 의 최댓값이 문장 `o` 이다. 현재 `o` 보다 큰 문장은 출제하지 않는다.
  - R2(토큰): 토큰화는 소문자 + 앞뒤 부호 제거 + 안쪽 `'` 유지, 하이픈은 쪼갬. `say` 가 있으면 `say` 를 토큰 원천으로 쓴다. 고유명사(이름·도시)는 낱말 목록에 `pos:"propn"` 으로 들어 있어야 한다.
  - R3(활용형): `works`·`worked`·`working` 같은 형태는 낱말의 `forms[].f` 에 명시하고, 그 형태의 `o` 는 `max(원형 o, 그 활용을 가르치는 문형 o)` 이다.
  - R4(보기): 오답 보기·오답 타일은 `o ≤ 현재` 인 낱말에서, 같은 품사 우선, **정답과 같은 `ko` 를 가진 항목 제외**(동의어 오답 방지), 보기가 모자라면(1~2주) 보기 수를 줄인다(최소 2).
  - R5(수동 단어): `role:"passive"` 낱말이 든 문장은 `scope:"listen"` 이며 듣기·대화에만 나오고 `recall`·`build`·`recognize` 의 정답·보기에는 쓰지 않는다. 화면에서 눌러 뜻을 볼 수 있다.
  - R6(세션): `recognize`·`recall` 은 **이 세션에서 소개 카드를 이미 본 낱말**과 이전 날짜 낱말만 묻는다(중간에 나갔다 와도 건너뛴 단어를 묻지 않는다).
- **3중 검사**
  1. **원고 린터**(`check_course.py`, 빌드 전): R1~R5 위반이 있으면 빌드 실패(§9.2).
  2. **실행 중 가드**(`LexiconGuard`): `LessonBuilder` 가 만든 문제를 화면에 올리기 전에 토큰 검사. 위반 문제는 **버리고** `dropped` 로 센다(앱은 계속 진행, 시험이 `dropped` 를 본다).
  3. **전수 시험**(`course_guard_all_test`): 출시 데이터 전체에서 모든 (주 x 일 x 종류 x 시드) 단위를 만들어 위반 0, 버려진 문제 비율 2% 미만을 확인한다(§14 KB).
- **자연스러움**: 제약 때문에 "I am Min. I like cat." 같은 어색한 문장이 나오지 않게, 문장 원고는 한 문장 단위로 독립 검수(§9.4)한다. 9주부터 Tatoeba 의 실제 문장 중 **그 주까지 배운 단어만으로 된 것**을 듣기용으로 일부(전체의 25% 이하) 섞는다(§9.1).

| L5 | 자유 대화 | **안내형**(AI 가 쉬운 질문을 하고 답 힌트 칩 2개) 17주~ → **자유**(주제 선택) 33주~ → **열린**(수준 제한 완화) 57주~ | R2~R4 |
- 열림은 **부드러운 잠금**이다: 아직 안 열린 칸을 누르면 "N주차부터 열려요" 안내와 [그래도 해 보기] 확인창이 나온다(기존 길의 `locked` 처럼). 코스 모드에서만 적용, 일본어·예전 길은 변하지 않는다.
- 하루 말하기 12분의 구성(`CourseModel.speak_plan(w, d)`, 새): D1~D3 = L1 5분 + L2 7분(열려 있으면), D4 = L3, D5 = 미션(L4)·자유(L5)가 열려 있으면 그것, 아니면 L3 반복, D6 = 점검 말하기, D7 = 사용자가 고른 칸.
- 단계가 오를수록 힌트가 줄어든다: L3 의 한국어 힌트·영어 모범 답은 8~16주 기본 표시, 17~32주 눌러서 표시, 33주~ 표시 없음(점수에 감점 없이 "힌트 사용" 만 기록).

## 5. 수준 맞춤 AI 대화 (R2, 2.1.0)

### 5.1 목표
AI 가 그 주까지 배운 단어·문형 안에서 말하게 하고, 벗어나면 **응답을 거르고**, 막히면 한국어로 돕는다. 폰 단독은 AI 가 없으므로 대본 대화(L3~L4)가 대신한다.

### 5.2 요청 계약 (새 선택 필드, 새 라우트 없음)
`POST /chat` 본문에 선택 필드 `course`(새)를 더한다. 없으면 지금과 100% 같다.
```json
{"lang":"en","stage":1,"month":1,"week":1,"scenario":{"id":"cafe_order"},"history":[],
 "course":{"w":24,"mode":"guided","simplify":false}}
```
- `course.w`: 1..72 정수. 범위 밖·문자열은 무시(기존 동작). `course.mode`: `"guided"`(17주~, 쉬운 질문 + `suggest` 2개) | `"free"`(33주~) | `"open"`(57주~) | `"mission"`. `course.simplify`: 사용자가 [쉬운 말로] 를 눌렀을 때 true.
- 서버는 `backend\content\course_levels.json`(새, 빌드가 만든 사본: `{"w": [[누적 활용형 목록], …]}` 약 2~3만 자)으로 허용 어휘를 안다. 파일이 없으면 `course` 를 무시하고 기존 `LEVEL` 동작(오류 아님).
- 응답은 기존 `reply`·`ko`·`reading`·`suggest`·`fix`·`fix_ko`에 선택 필드 `level`(새): `{"oov": ["word", …], "source": "ai"|"fallback"}`.
- **한국어 도움**: 본문에 `help_ko`(새, 문자열 ≤ 120자)가 있으면 서버는 대화를 이어 가지 않고 `{"help": {"en": "...", "ko": "..."}}` 를 돌려준다(사용자가 한국어로 하고 싶은 말 → 그 주 어휘로 만든 영어 한 문장 + 한국어 설명). 같은 수준 검사를 통과한 것만 보낸다.

### 5.3 프롬프트와 출력 검증
- 시스템 프롬프트(영어)에 넣는 것: 학습자는 한국인 성인 초급이고 **N주차**; 문장 수 ≤ 2, 문장당 단어 수 상한(1~8주 6, 9~16주 8, 17~32주 12, 33주~ 16); 이번 주와 지난주의 **목표 단어·문형**을 자주 쓰기; 관용구·구동사 금지(33주 전); 17주 전에는 허용 어휘 전체 목록을 프롬프트에 넣고(약 700단어 이하), 이후는 최근 8주 목록 + "나머지는 가장 흔한 1,000단어 이내"; 학습자 말을 한국어로 번역하지 않는다; 항상 질문 하나로 끝낸다(안내형). 대화 세션은 기존처럼 OpenCode 세션을 유지하므로 목록은 세션당 한 번만 간다.
- 검증 `level_check(reply, w)`(파이썬, 새, 서버 안): 토큰화는 §3.3 R2 와 같다. 대문자로 시작하는 문장 중간 낱말은 고유명사로 허용. 허용 초과 단어(`oov`) 개수가 한도(1~16주 0, 17~40주 1, 41주~ 2)를 넘거나 문장 수·길이 초과면 불합격. 불합격이면 "다음 단어는 학습자가 모릅니다: … 이 단어 없이 다시 말하세요" 를 붙여 **최대 2번** 다시 요청. 그래도 안 되면 데이터의 **안전 대사 목록**(`Really?`, `I see.`, `Can you say that again?` 같은 그 주 허용 어휘만으로 된 것, 시나리오별 `ai_fallback`)으로 대체하고 `level.source="fallback"`. 앱은 `oov` 단어를 밑줄로 보여 주고 누르면 뜻(코스 낱말 목록 → `/reading/gloss`)을 띄운다.
- 막힘 도움 3단계(앱, `TalkView`·`MissionScreen`): 15초 입력이 없으면 ① 한국어 뜻 보기(기존 `ko`) → ② 말할 문장 후보(`suggest`) → ③ [한국어로 말해 보기](`help_ko`) → 따라 말하기.
- 시험: 가짜 엔진(`test_fake_opencode.py` 방식)으로 ① 수준 밖 단어가 섞인 응답이 재요청·대체되는지 ② 같은 단어를 계속 고집하는 엔진에서 2번 뒤 대체 대사가 나가는지 ③ `course` 없는 요청이 기존과 같은 응답인지. 실제 DeepSeek 준수율은 **미검증으로 남기고** R2 때 20개 대화로 측정해 보고한다.

## 6. 하루 45분 계획

### 6.1 홈 "오늘 할 일" 구성
- 코스 모드(영어)의 홈은 `DayPlan.today()`(새)가 정한 **블록 4개**를 보여 준다. 시간은 분 단위 글로만 보인다.
| 블록 | 기본 분 | 내용 | 완료 판정 |
|---|---|---|---|
| 새 내용 | 15 | 오늘 칸(주 w, 일 d)의 종류에 따른 단위(§2.2). D5=말하기, D6=점검, D7=자유 | 단위를 끝까지(숙달 루프 포함) |
| 복습 | 10 | FSRS 밀린 카드(기존 `ReviewView`) | 오늘 복습한 카드 ≥ min(밀린 수, 15) 또는 세션 1회 종료 |
| 듣기 | 8 | 배운 문장 듣기 세트(8문제, 속도 선택) | 세트 종료 |
| 말하기 | 12 | 사다리 칸(§4) | 5문장 이상 말했거나 자가 평가 완료 |
- **단계별 분 배분**(합계 45 고정, `CourseModel.unit_minutes(w, d)`):
| 단계 | 새 내용 | 복습 | 듣기 | 말하기 | 이유 |
|---|---|---|---|---|---|
| S0 (1~4주) | 18 | 5 | 12 | 10 | 소리 훈련 비중↑, 쌓인 카드 적음 |
| S1~S2 (5~32주) | 15 | 10 | 8 | 12 | 기본 |
| S3~S4 (33~60주) | 12 | 12 | 8 | 13 | 카드가 쌓임, 말하기↑ |
| S5~S6 (61~72주) | 10 | 10 | 10 | 15 | 일터 듣기·말하기↑ |
- 복습할 카드가 0이면 복습 블록의 시간은 그날 듣기에 더해진다(합계 45 유지). D6(점검 날)은 새 내용 15분이 점검 12분 + 약점 3분, D7 은 새 내용 블록이 "자유 15분"(선택 활동)이다.
- 홈 시작 버튼 글: "오늘 45분 시작"(할 일이 남았을 때) / "더 연습하기". 인사 줄: "오늘 45분 중 20분 했어요."(마친 블록의 분 합계). 진행 글은 **`CourseModel.progress_label(kind, value, target)` 한 함수**에서 만든다(REVIEW.md).
- 하루 목표(`daily_goal_min`, 기본 10)는 코스 시작 때 "하루 목표를 45분으로 바꿀까요?" 확인(§15.3.1 Q5, 추천: 예). 이 설정은 동기화 대상이다(`SyncDoc` 화이트리스트).

### 6.2 밀렸을 때 따라잡기 규칙
진도는 **달력이 아니라 "한 칸을 끝냈는가"**로 나아간다. 쉬어도 칸이 건너뛰어지지 않는다.
| 번호 | 상황 | 규칙 |
|---|---|---|
| U1 | 하루 이상 쉼 | 다음 칸은 그대로. 홈에 "예정보다 N주 늦음"(예정 = 시작일부터 7일에 1주, 예비 6주를 뺀 달력과 비교)을 **알림으로만** 표시(감점·잠금 없음) |
| U2 | 밀린 복습 카드 ≥ 40 | **복습 우선 모드**: 그날 새 내용은 절반 분량(단어 3개까지)으로 줄이고 복습 20분 + 듣기 5 + 말하기 5 + 새 내용 15 → 합 45. 밀린 카드가 25 이하가 되면 해제. 3일 연속 복습 우선이면 4일째는 새 내용을 정상으로 돌려 무한 보류를 막는다 |
| U3 | 7일 이상 쉬었다 돌아옴 | 첫날 **복귀 점검**(`recap`: 직전 주 점검 문항 6개)과 복습 위주 하루. 통과하면 정상 진행 |
| U4 | 21일 이상 쉬었다 돌아옴 | U3 + 직전 2주의 "완료" 표시를 풀어(카드·기록은 유지) 다시 하게 한다 |
| U5 | 주간 점검(D6)을 안 하고 다음 주로 가고 싶음 | 다음 주는 "미리 해 보기"(부드러운 잠금)로 열리고 점검은 **미완료 표시**가 남는다. 3일 뒤 홈이 한 번 다시 묻는다 |
| U6 | 점검 불합격 2번 | §7.1 의 규칙(약함 표시로 진행 허용) |
| U7 | 예비 주 | 달력 78주 중 6주는 예비다: 단계 끝(16·32·48·60·68·72주) 뒤에 각 1주씩 "예비 주"를 홈 문구로 안내(별도 데이터 없음, 시작일 기준 예정 계산에만 반영) |
- 모든 규칙은 `DayPlan.today(snapshot)` 의 입력(`due`, `away_days`, `check_pending`, `w`, `d`, `blocks_done`)만으로 정해지는 **순수 함수**여야 한다(시험 가능).

## 7. 점검

### 7.1 매주 미니 점검 (D6, 약 12분)
- 구성 12문제(그 주까지 배운 범위): 듣고 뜻 고르기 4, 뜻 보고 영어 쓰기 3, 문장 조립 2, 말하기 2(따라 말하기·문형 바꿔 말하기), 대화 이해 1. 문제는 이번 주 70%, 지난 3주 30%.
- 판정: **자동 채점 문제 10개 중 8개 이상(80%)**이면 통과. 말하기 2개는 PC 에서 `/score` 정확도 60 이상이면 "말하기 통과", 폰 단독은 자가 평가라 **통과 판정에 넣지 않고** "말하기 미검증" 표시.
- 불합격: 틀린 문제의 낱말·문형으로 **약점 복습 세트**(최대 10분)를 즉시 제안하고, 다음 날 새 문제로 다시 점검한다. **2번 불합격이면** 진행은 허용하되 그 주에 **약함 표시**를 달고 약점 낱말을 복습 카드로 다시 넣는다(`relearn`: 지금 예정으로). 입문(0단계)은 80%가 아니면 1단계가 열리지 않는다(부드러운 잠금 안내, 사용자가 확인하면 열 수 있음).
- **건너뛰기(배치)**: 어느 주든 [점검으로 건너뛰기]를 누르면 그 주 점검을 보고 **90% 이상**이면 그 주를 "완료"로 표시한다(카드 추가 없음). 기존 영어 사용자가 이미 아는 주를 넘기는 길이다.

### 7.2 월말 말하기 평가 (4·8·12…주 D6)
- 구성: 읽기 2문장(따라 읽기) + 질문 2개에 대답 + 30초 자기소개(주차가 오르면 길어짐). 원고에 `speak_prompts`(월마다 3개)가 있다.
- 채점(PC): `/stt` 전사에서 기대 표현이 든 비율(`expect_any` 중 하나 이상 + 목표 단어 일치율)과 `/score` 정확도·유창성을 합쳐 0~100. 폰 단독: 5항목 자가 평가 루브릭(또렷함·막힘·문형 사용·되묻기 사용·자신감) 합 100, "자가 평가" 표시.
- 기준: **70점 이상** 통과. 미만이면 **말하기 보강 3일**(그 달 가장 낮았던 문장 5개를 L1·L2 로 반복)을 제안하고 한 번 다시 본다. 다시 70 미만이면 진행은 허용, 다음 달 말하기 블록을 5분 늘린다(듣기에서 5분 이전)·"약함" 표시. 점수·날짜·시도 수는 `course.json` 에 남긴다. 음성 파일 보관은 사용자 결정(§15.3.1 Q6).

### 7.3 72주차 최종 평가
- 3부: ① 상황 미션 5개(무작위, 힌트 없이 목표 80%) ② 듣기 20문제 ③ 말하기 평가(월말 방식) + 어휘 표본 100개. §1.1 의 "가능" 기준과 대조한 **결과 카드**(영역별 O/X)를 보여 주고, 미달 영역의 복습 계획을 제안한다. R4(2.3.0)에서 구현.

- 새 미션 19개(# 6, 7, 9~14, 16~19, 21~27)와 기존 8개 = 27개. 최종 평가(§7.3)는 이 27개 중 무작위 5개로 시험한다. 정확한 개수·내용은 R2~R4 뼈대 작업이 확정한다(늘거나 줄 수 있음).
- 미션 형식은 기존 `missions.json` 그대로(대본 `script`, 목표별 규칙 `match`·`pos`·`neg`, `min_stage`) + `min_week`(새). 새 미션의 규칙 품질 검사는 기존 `test_missions.py --lint` 와 독립 문장 시험(`v170` B2t 방식)을 따른다. 어휘는 해당 `min_week` 까지 배운 범위의 **영어 정답 예시**만 힌트로 쓴다.

### 8.2 단계별 의존
도착·정착(R3), 구직·일터(R4) 미션은 해당 주 어휘를 먼저 배운 뒤에만 열린다(`min_week`). 미션을 하다 막히면 해당 주 복습으로 가는 링크("이 표현은 37주차 은행에서 배웠어요")를 결과 화면에 넣는다(R3).

### 8.3 일터 유형
S5 는 카페·식당(주문 받기), 소매(계산·포장·환불 규정), 청소(용구·지시), 창고(안전·장비·교대), 농장(날씨·작업 지시)의 공통 말과 유형별 어휘 묶음을 가르친다. 유형은 "내 일자리" 선택(홈 설정, 새 prefs `course_job_kind`, 기기 전용)으로 어휘 묶음 우선순위만 바꾸고 진도는 같다(R4).

### 8.4 캐나다 억양 듣기
- 앱에 캐나다 음성이 없다(F12). R1~R3 은 **텍스트 노트**(캐나다 발음 특징: "about" 의 모음, "z" = zed, 되묻기 "Sorry?", 말끝 "eh")와 **목소리 여러 개**(미국 여성·남성 Kokoro 음성 4종 이상 섞기)로 듣기 다양성을 높인다.
- 실제 캐나다 억양 녹음은 **사용자 승인 + 직접 녹음·동의가 있는 자원자 녹음만** 쓴다(저작권·개인정보, `check_no_media.ps1` 은 `*.mp3 *.m4a *.ogg *.wav` 를 막으므로 허용 폴더를 정해야 함 → R4 에서 별도 설계). 승인이 없으면 R4 도 텍스트 노트까지만.

| `ORDER` | 문장·대화 줄의 토큰 중 `o` 가 문장 `o` 보다 큰 낱말(= 수준 밖) |

### 9.3 뜻·읽기 교차 확인
1. **뜻(ko)은 문맥 있는 쌍**으로만 쓴다(낱말 + 그 뜻이 들어간 예문). `gloss_en.json`(AI 사전)은 사실로 쓰지 않는다(F14).
2. **독립 검수(`X1`, `X2`)**: 작성자와 다른 `worker-hard` 가 새 컨텍스트로 100% 항목의 영어 정확성·한국어 자연스러움·품사·수준·캐나다 철자 일관성·`say` 를 판정(`OK`/`M`/`C`)한다. 검수자의 능력은 **계획 오류 주입**으로 잰다(§14 X-2).
3. **보조 신호**(경고만, 단독으로 합격·불합격 아님): ① 한국어 → 영어 뒤번역을 독립 모델(개발 PC 로컬 또는 DeepSeek)로 만들어 핵심 낱말 겹침이 낮으면 표시 ② WordNet + `omw-1.4` 한국어 표제어와 `ko` 의 겹침(한국어가 `omw-1.4` 에 있는지·커버리지는 **측정 전 추측**) ③ 품사·활용형은 `nltk` WordNet 으로 확인.
4. **숫자·시간·금액 읽기는 코드가 만든다**: `numbers_en.py` 가 `say` 를 만들고 린터가 대조한다(AI·손으로 쓰지 않음). 알파벳 글자 이름·소리 항목의 `say`(예: `ay`, `bee`)와 소리 연습 낱말은 **사용자가 실제 소리를 들어 확인**한다(§15.3.1 Q10, 표본 샘플 파일은 K1 도구가 만들지 않고 오케스트레이터가 앱으로 재생).
5. **한국어 설명**(`grammar_ko`)은 짧고 규칙형으로: 어순·관사·시제 설명이 사실과 맞는지 독립 검수 + 사용자 표본.

### 9.4 사람 검수 표본과 오답률 목표·측정
- **오류 등급**: **C(중요)** = 영어가 틀림(문법·철자·뜻), 한국어 뜻이 틀림, 숫자·시간 읽기가 틀림, 미국식만·영국식만을 캐나다 표준으로 잘못 표기, 잘못된 사실. **M(주의)** = 어색하지만 통한다, 한국어 어색, 품사·활용 표기 불일치, 수준(단어) 부적합. **m(경미)** = 오탈자·부호.
- **목표(릴리스 합격선)**: 린터 위반 0, 독립 검수 100% 후 **C 잔여 0**, 사람 표본 **300개에서 C 0건**(95% 신뢰 상한 약 1%: 0/300 의 "3의 법칙"), M ≤ 3건(Wilson 95% 상한 약 2.9%), m 은 수정 목록으로.
- **표본 추출**: `sample_sheet.py --n 300 --seed <릴리스별 고정>` 이 층화 추출(낱말 90, 문장 120, 대화 줄 50, 한국어 문법 설명 40)한 CSV(`id,type,en,ko,say,note,verdict`)를 만든다. 사용자가 **한국어 자연스러움·뜻**을 판정(약 50분), 영어 정확성은 독립 검수 AI 가 맡고 **영어 원어민 또는 영어 교사에게 100개 선택 확인**(§15.3.1 Q1, 추천)을 권한다.
- **불합격 처리**: C 가 1건이라도 나오면 같은 종류를 전체에서 찾아 한 번에 고치고(`REVIEW.md` 방식) **새 표본 300개**를 다시 본다. 2번째도 불합격이면 접근 재검토(오케스트레이터).
- **출시 후 측정**: R2 부터 레슨 카드의 [잘못된 내용 신고](새, `user://course_reports.json` 기기 전용, 설정에서 복사)로 모은다. 목표: 표시된 1,000항목당 신고 확정 C ≤ 1.

### 9.5 코스 차단어·개인정보
- 기존 레슨 차단어 `BLOCK_EN` 은 `knife`, `drug(s)`, `alcohol*`, `cancer`, `prison`, `hell` 등을 막지만 워홀 일터·병원 상황에는 필요한 단어가 있다. 코스는 **별도의 좁은 차단 목록**(`course_src\en\policy.json`)을 쓴다: 욕설·성적 노골 표현·혐오 표현·폭력 묘사 금지, `knife`(주방 안전)·`drugs`/`pharmacy`(약국)·`alcohol`(술을 파는 일터에서 나이 확인)은 허용(해당 주에서만).
- 대사의 이름은 `policy.json` 의 가상 이름 목록, 전화번호는 `555-01xx` 형식, 주소는 가상 도시·거리. 사용자의 개인 정보(이름·사진·위치)는 코스 데이터에 들어가지 않는다. `course.json` 에는 진도만 있고(§10.6) 녹음 파일은 사용자가 승인한 경우에만 기기 안에 저장한다.

### 11.2 기존 영어 사용자가 코스를 만나는 방법
- 영어 레슨 탭과 홈에 **[새 코스로 시작]** 카드가 생긴다(`CourseData` 가 있고 `course_mode` 가 없을 때만). 누르기 전까지 화면은 지금과 같다(D13).
- 시작하면 확인 시트: "0부터 72주 코스예요. 이미 아는 주는 [점검으로 건너뛰기]로 넘길 수 있어요. 예전 12개월 길은 [레슨] 화면의 [예전 길]에서 계속 쓸 수 있어요." + 하루 목표 45분 변경 제안.
- 코스 모드에서도 [예전 길]·[예전 12개월 로드맵]이 항상 남는다. 모드를 바꿔도 **어느 쪽 기록도 지워지지 않는다**.

### 11.3 기존 시험 보호
- 코스 선택 전이 기본이므로 **기존 시험의 기대값은 하나도 바뀌지 않는다**. 단, 레슨·홈 화면에 "새 코스로 시작" 카드가 더해지면서 화면 구조(위치·개수) 단언이 깨지는 시험은 E5(레슨 쪽) 또는 E6(홈 쪽)이 **카드를 더한 만큼만** 고친다(§13.3 에 허용 목록). 지워지거나 느슨해진 단언은 금지(`REVIEW.md`).
- 다운그레이드(옛 버전 설치): `course.json`·`course_mode` 는 모르는 파일·키라 무시된다(데이터는 남음).

### 11.4 동기화·카드 상한 (R3)
- R1~R2: `course.json` 기기 전용. PC 와 폰이 **각자 진도**를 가진다(예전 길의 "레슨 횟수는 이 기기만"과 같은 한계, 홈에 한 줄 안내). 복습 카드는 지금처럼 동기화된다.
- R3: 주 완료·점검 통과를 `checks` 집합에 `ec-<n>-w<k-1>`(예: 13블록 3번째 주 = `ec-13-w2`)로 실어 동기화한다(F16: 앱·허브의 키 형식을 이미 통과 → 스키마 변경 0). 카드 상한 3,000 → **6,000**(`Progress.MAX_REVIEW`, `SyncDoc.MAX_CARDS`, `sync_hub.py` `LIMITS["cards"]` 7,000)과 관련 동기화 시험을 함께 올린다(카드 수 추정: 코스 카드 약 2,300 + 다른 출처(대화 교정 대화당 8장, 읽기, 일기) → 3,000 초과 가능, **추측**). 허브 요청 크기 한도는 R3 작업자가 실측한다.

## 13. 작업 분할 (R1 = 2.0.0)

### 13.1 규칙 (모든 작업 공통)
- 담당은 전부 `worker-hard`(구현·콘텐츠 작성·검수). 검토는 `reviewer`(§13.4). 문서 작업 Z 도 `worker-hard`.
- 작업마다 **별도 worktree** `D:\Ai\언어\app_wt\v200_<작업>`, 브랜치 `v200/<작업>`(기존 `ja_w`, `ja_z`, `rev_base` 는 건드리지 않는다). 오케스트레이터가 §13.2 순서로 합친다. 다른 작업의 파일은 읽기만, 고칠 일이 생기면 오케스트레이터에게 보고한다.
- 임시 파일·로그·가짜 APPDATA 는 `<scratchpad>\w_<작업>\` 안에만. 시험이 쓰는 사용자 파일은 `user://test_*` 만(시험 보호). 콘텐츠 일회용 스크립트도 scratchpad 에 둔다. **`backend\tools\` 에 새 추적 파일을 만들지 않는다**(`-ScanOnly` 가 막는다). 콘텐츠 도구는 `course_src\tools\`.

- 색은 `Pal` 토큰만(`Color("#…")` 금지), 글자 크기 `Ds.fs(n)`/`UI.label` 변형(최소 12), 눌리는 것은 `Button`/`BaseButton`, 도형은 `GlyphIcon`(이모지·도형 글자 금지). 요청은 기존 경로(`SpeakDrill.request`·`Api`)만: 새 `HTTPRequest`·`OS.shell_open` 금지.

### 13.5 소유권 검사 스크립트 (오케스트레이터·검토자가 합치기 전에 돌린다)
저장소 루트에서 실행. 두 작업이 같은 파일(또는 같은 폴더 아래)을 소유하면, `mod` 인데 파일이 없으면, `new`/`newdir` 인데 이미 있으면 `FAIL` 을 찍고 종료 코드 1.
```powershell
@'
import sys, os
doc = open("docs/v200_design.md", encoding="utf-8").read()
blk = doc.split("<!-- OWN-BEGIN -->")[1].split("<!-- OWN-END -->")[0]
owner, dirs, bad = {}, {}, 0
rows = []
for line in blk.strip().splitlines():
    task, kind, path = line.split(None, 2)
    p = path.strip().replace("\\", "/")
    rows.append((task, kind, p))
for task, kind, p in rows:
    key = p.lower()
    if kind == "newdir":
        if not key.endswith("/"):
            print("FAIL newdir must end with /:", p); bad += 1
        dirs[key] = task
        if os.path.exists(p) and os.listdir(p):
            print("FAIL new dir already has files:", p); bad += 1
    else:
        if key in owner and owner[key] != task:
            print("FAIL overlap:", p, owner[key], task); bad += 1
        owner[key] = task
        exists = os.path.exists(p)
        if kind == "mod" and not exists:
            print("FAIL missing existing file:", p); bad += 1
        if kind == "new" and exists:
            print("FAIL new file already exists:", p); bad += 1
for f, t in owner.items():
    for d, dt in dirs.items():
        if f.startswith(d) and t != dt:
            print("FAIL file inside another task's dir:", f, t, dt); bad += 1
for d1, t1 in dirs.items():
    for d2, t2 in dirs.items():
        if d1 != d2 and d2.startswith(d1):
            print("FAIL nested dirs:", d1, d2); bad += 1
print("files", len(owner), "dirs", len(dirs), "tasks", len({r[0] for r in rows}), "FAIL" if bad else "OK")
sys.exit(1 if bad else 0)
'@ | python -X utf8 -
```
기대 출력: 마지막 줄 `files 81 dirs 4 tasks 18 OK`(81 은 위 표의 `new`·`mod` 줄 수, 문서를 고치면 같이 고친다. 설계자가 작성 직후 직접 돌려 이 출력을 확인했고, 겹침·없는 파일·이미 있는 새 파일·폴더 안 남의 파일을 일부러 넣은 복사본에서 각각 `FAIL` 이 나오는 것도 확인했다).

## 요약 (12줄)
1. 대상은 영어 0부터의 한국인 성인, 72주(블록 18개)·하루 45분(378시간, 달력 78주 예비 6주). 목표는 CEFR A2+ 전반 + 워홀 상황 27개 안 B1 낮은 수준이며 **일반 B1 은 보장하지 않는다**(Cambridge 안내 시간 근거, 합성 음성·사람 피드백 없음 등 한계를 문서·앱에 적는다).
2. 7단계: 입문 1~4주, 기초 문장 5~16, 생활 17~32, 도착·정착 33~48, 일 찾기 49~60, 일터 61~68, 종합 69~72. 어휘 능동 약 1,800 + 수동 약 950, 매주 새 단어 약 25·문형 3~5·미니 대화 1.
3. 새 레슨은 소개 → 알아보기 → 떠올리기 → 조립 → 듣기 → 말하기. **앱 안의 순수 클래스**(`LessonBuilder`·`LexiconGuard`)가 만들어 AI 호출 0, 정답은 구성으로 보장. 배운 말만 나오는지는 낱말·문장의 도입 순서 `o=w*10+d` 로 **원고 린터 + 실행 중 가드 + 전수 시험** 3중 검사.
4. 말하기 사다리 5단(따라 말하기 1주, 바꿔 말하기 2주, 대본 대화 8주, 미션 13주(AI 25주), 자유 대화 17·33·57주). 수준 맞춤 AI 대화는 R2: `/chat` 에 선택 필드 `course` + 서버 어휘 검사·재요청·안전 대사 + 한국어 도움 3단계(새 라우트 없음).
5. 하루 45분은 블록 4개(새 내용 15·복습 10·듣기 8·말하기 12, 단계별 조정). 진도는 달력이 아니라 칸 기준, 밀리면 복습 우선(밀린 카드 40)·복귀 점검(7일)·재개(21일). 주간 점검 80%, 월말 말하기 70점, 부드러운 잠금.
