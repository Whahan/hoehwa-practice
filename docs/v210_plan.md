## 1. v2.1.0 목표와 공개 기한

### 1.1 버전 목표 (사용자 관점)

2.0.0에서 알파벳과 기초 문장(1~16주)을 마친 사용자가 **17~32주(S2 생활 말하기: 과거·날씨·계획·교통·식당·쇼핑·전화·건강·집)**로 끊김 없이 올라가면서, "가르친 말만 나온다"는 약속을 레슨 바깥의 **AI 대화·미션·쉐도잉·받아쓰기**까지 넓히는 릴리스다. 17주차부터 열리는 안내형 AI 대화와 25주차부터 열리는 AI 미션에서 AI가 사용자가 배운 어휘·문형 범위 안에 머물고(PC와 폰 모두), 단발성 상황극 대신 **캐나다 워홀 연속 이야기 회화(제안 A)**로 전날 상황을 이어 가며 매일 말할 이유를 만든다. 아울러 원해서 켠 사용자에 한해 기기 안에만 안전하게 남기는 **내 녹음 비교(제안 B + 월말 평가 녹음 비교)**로 처음과 한 달 뒤의 내 영어 소리를 나란히 들으며 성장을 체감하게 한다.

### 1.2 공개 기한 (간격 규칙)

- **기준일**: `v2.0.0` 공개일 **2026-11-19**.
- **간격 규칙**(`ROADMAP.md`, `docs/v200_design.md` §12): 제때(주 1칸) 공부하는 사용자가 다음 릴리스의 첫 주(17주차)에 닿기 **4주 전(= 16주차 도달 4주 전, 12주차 말)**까지 공개한다.

- **권장 목표일**: **2027-01-28** (상한 대비 예비 2주 확보, `docs/v201_plan.md` §5.2 기준 유지). 작성일(2026-11-27) 기준 상한까지 약 10.5주 남아 있다.

## 3. 이야기 회화(A)와 17~32주 원고의 관계

### 3.1 핵심 문제의식과 장면 매칭 원칙: 시즌제 연속 서사

사용자 승인 제안 A의 전체 여정(**밴쿠버 공항 → SIN → 은행 → 셰어하우스 → 면접 → 동료**)은 72주 커리큘럼의 S2~S5(17~68주) 전체에 걸쳐 있다(`skeleton.json` 기준 공항·SIN·은행·방 계약은 33~44주, 면접·동료는 53~68주). 2.1.0의 17~32주(S2 생활 말하기)에 SIN·은행·면접 전문 어휘를 미리 당겨 넣으면 **"배운 말만 나온다"** 원칙과 충돌한다.

따라서 이야기 회화는 **72주 원고와 1:1로 호흡하는 3시즌 연속 서사**로 설계하고, 2.1.0은 **엔진 + 시즌 1(17~32주)**을 구현한다.

- **시즌 1 (2.1.0, 17~32주 — 밴쿠버 워홀 첫 달 적응·생활편, 16장면)**:
  - **17~20주 (과거 시제)**: 밴쿠버 도착 직후 호스텔(`Harbour Hostel`)에서의 첫날 밤~첫 주말 회상("어제 밴쿠버에 왔어요", "공항에서 버스를 탔어요", "주말에 카페·시내에 갔어요"). 입국심사 전문 용어 없이 17~20주 과거형으로 워홀 시작의 몰입감을 즉시 준다.
  - **21~24주 (날씨·계획·약속·교통)**: 캐나다 겨울 날씨와 옷(`toque`, `runners`) 준비 → 주말 계획 세우기 → 새 친구(가상 인물)와 약속 잡기 → 길 묻고 버스·대중교통(`transit pass`) 타기.
  - **25~28주 (식당·쇼핑·전화·건강)**: 첫 식당 주문·팁 → 겨울옷 사이즈 교환·환불 → 전화로 용건 말하고 이름·번호 철자 불러 주기(방 문의/예약 맛보기) → 감기 걸려 약국 가기.
  - **29~32주 (방·비교·조언·종합)**: 셰어하우스 방 둘러보기 → 방 두 곳 가격·거리 비교 → 분실물·생활 문제 조언 구하기 → 첫 달 생활 정리(다음 시즌 정착·서류 편 예고).
- **시즌 2 (2.2.0, 33~48주 예고)**: 공항·입국(회상/서류 확인) → SIN 신청 → 은행 계좌 → 휴대폰 → 본격 방 계약·집주인·룸메이트 → 병원.
- **시즌 3 (2.3.0, 49~68주 예고)**: 이력서 직접 제출 → 구직 전화 → 면접 → 첫 출근·동료.
- **원고 공유 원칙**: 각 주 원고(`w017~w032.json`)의 `scene`·미니 대화(`d0017~d0032`)와 이야기 회화가 같은 가상 인물(`policy.json` 허용 이름: `Min`, `Sam`, `Anna` 등)과 가상 장소(`Maple Cafe`, `Harbour Hostel`, 전화번호 `555-01xx`)를 공유한다. D1~D4 레슨에서 배운 표현을 바로 그 주의 이야기 회화에서 이어서 쓰게 한다.

### 3.2 장면 수와 주당 빈도

- **장면 수**: 2.1.0은 **16장면(17~32주, 주당 1장면)**. 한 장면은 2~3회 짧은 회화(회당 4~6턴, 약 3~5분 **(추측)**)로 구성해 부담을 낮춘다.
- **주당 빈도**: 권장 **주 2~3회**(하루 45분 중 말하기 12분 블록 안, 특히 D5 말하기 날·D7 자유 날에 배치; 원하면 매일 이어 하기 가능). 하루 45분 총량을 늘리지 않는다.

### 3.3 기억해야 할 것의 범위와 개인정보 원칙

- **저장 구조**: 대화 원문 전체를 저장하지 않고, 회화가 끝날 때 **구조화된 짧은 이야기 기억 슬롯**만 기기 전용 파일(예: `user://course_story.json`, `SyncDoc` 동기화 제외, `allowBackup=false`)에 저장한다.
- **기억 화이트리스트(허용 항목만)**:
  1. 현재 에피소드·진행 회차·날짜
  2. 가상 이야기 속 선택과 사건 태그 최대 **5~8줄**(총 **300~500자 상한** **(추측)** — 예: "Harbour Hostel에 묵는 중", "Sam과 토요일에 Maple Cafe에 가기로 함", "파란 겨울 재킷을 M으로 교환함", "감기약을 샀음").
- **개인정보 원칙**:
  - 사용자의 실제 성명·실제 주소·실제 전화번호·생년월일·여권/SIN/계좌 번호·민감한 실제 건강 이력은 **AI가 묻지 않고 기억 슬롯에도 저장하지 않는다**(프롬프트 금지 지시 + 저장 전 이메일·전화번호 형식 등 패턴 필터링).
  - 저장된 기억 슬롯은 다음 회차 AI 요청 프롬프트에 포함되어 선택한 AI 업체(PC OpenCode/DeepSeek 또는 폰 선택 업체)로 전송된다. 따라서 **2.0.2 개인정보 동의 안내에 "이야기 요약 전송"을 명시**하고, 화면에서 사용자가 **기억 내용을 직접 보고 항목별 삭제·전체 초기화**할 수 있게 한다.
  - 앱 로그·동기화 파일·백업·오류 신고 파일에 대화 원문과 기억 내용이 기록되지 않는다(0건).

### 3.4 AI 실패 시 대체

- **세션 시작 시 AI 불가**(키 없음·오프라인·429 한도 초과·5xx·시간 초과): 해당 주의 **미니 대본 대화(L3, `d0017~d0032`)** 또는 에피소드별 **고정 대본(2~3턴)**으로 자동 전환한다. 에피소드 완료 처리가 가능하며, 기억은 "해당 장면 완료" 기본 태그만 기록해 이야기가 끊기지 않는다.
- **대화 도중 턴 실패 또는 `level_check` 2회 재요청 후에도 불합격**: `docs/v200_design.md` §5.3대로 해당 주 허용 어휘 100%로 만든 **시나리오별 안전 대사(`ai_fallback`)**로 대체(`level.source="fallback"`). 요금 보호를 위해 네트워크 오류·한도 초과 시 자동 재시도 0회 원칙(2.0.2)을 그대로 지킨다.
- **기억 요약 갱신 실패**: 직전 기억 슬롯을 그대로 유지하고 에피소드 완료만 기록한다(크래시·데이터 손실 0).

## 4. 내 녹음 비교(B)의 개인정보 원칙과 최소 범위

### 4.1 기존 원칙과의 관계

기존 앱은 **사용자 녹음을 디스크에 남기지 않는 것**을 기본 원칙으로 삼아 왔다(`ROADMAP.md`, `README.md`). 다만 `docs/v200_design.md` §15.3.1 Q6(월말 말하기 평가 녹음 기기 내 보관, 최대 20 MB)과 2026-11-27 사용자 승인 제안 B(기준 문장 5개쯤 처음과 한 달 뒤 나란히 듣기)는 모두 **"직접 켠 사람만, 기기 안에만, 언제든 삭제"** 조건으로 승인되었다. 2.1.0에서는 두 기능을 **하나의 "내 녹음 비교" 모듈**로 통합해 동의·저장·삭제 규칙을 단일화한다.

### 4.2 개인정보 원칙 (비타협 규칙)

1. **기본 꺼짐(Opt-in)**: 명시적 동의("녹음은 이 기기 안에만 저장되고 PC·다른 기기·인터넷으로 나가지 않아요. 언제든 지울 수 있어요.") 후 켜기 전까지는 **어떤 녹음도 디스크에 저장하지 않는다(0바이트)**.
2. **기기 내부 비공개 저장소 전용**: 앱 비공개 내부 폴더(예: `user://voice_compare/`)에만 저장. PC↔폰 동기화(`SyncDoc`) 제외, 안드로이드 자동 백업(`allowBackup=false`) 제외, 외부 공유·파일 내보내기 기능 없음, AI 서비스로 전송 없음.
3. **용량 상한 20 MB**: `v200_design.md` Q6 기준 유지. 16 kHz 모노 16-bit WAV 기준 5초 클립 1개 ≈ 160 KB로, 20 MB면 약 125개 클립을 담을 수 있어 **(추측)** 18개월 동안 기준 문장 5개 × 월 1회(90클립)와 월말 평가를 충분히 수용한다. 상한 근접/도달 시 저장 전 안내하고, 사용자가 오래된 중간 녹음을 지우거나 오래된 중간 스냅샷부터 정리하게 한다(가장 처음 녹음은 자동 삭제하지 않음).
4. **언제든 삭제**: 녹음 개별 삭제, [녹음 모두 지우기] 버튼, 사용 용량(MB 단위, 5자리 숫자 표시 금지)을 항상 제공한다. 설정의 "모든 기록 지우기"와의 관계는 §6 D2에서 확정한다.
5. **배포·시험 격리**: `check_no_media.ps1`·`publish_release.ps1 -ScanOnly` 무결성 유지, 시험은 `user://test_*` 격리.

### 4.3 최소 범위 (2.1.0 MVP)

- **기준 문장 5개 고정 세트**: 1~16주 핵심 어휘·문형만으로 구성된 자기소개·인사·주문·일상 5문장(어느 주차에서 켜도 바로 녹음 가능).
- **월말 말하기 평가 연동**: 켜져 있을 때만 4·8·12·16·20·24·28·32주 월말 평가 완료 시 녹음을 자동 저장(꺼져 있으면 점수·전사만 저장).
- **나란히 듣기 화면**: 같은 기준 문장(또는 같은 월말 문항)에 대해 **[처음(또는 이전) 듣기]** 와 **[최근 듣기]** 2개 재생 버튼 + 녹음 날짜·채점 점수(있으면) 나란히 표시. 파형 시각화·억양 오버레이·오디오 편집·공유는 넣지 않는다.
